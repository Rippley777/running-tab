## Delivered workflow

- Native bounded discovery and manual linking support canonical paths, worktrees, repositories without remotes, and moved directories (filesystem identity on Unix). Discovery never creates clients or projects. Discovered repositories start in Manual/disabled mode; connecting them does not start collection.
- Explicit Assisted/Automatic collection uses a 30-second native poll while the desktop app runs. Automatic is opt-in and still produces reviewable sessions; neither mode automatically creates billable records. Manual uses the existing timer/forms. Native inactivity is inferred from approved file metadata, not device-input surveillance.
- Defaults: 10-minute idle threshold, 5-minute short-gap merging, 5-minute minimum suggestion; editable in tracking setup. File changes must bracket an interval inside the merge threshold. Branch transitions, commits, cold-start baselines, sleep/restart gaps, ignored generated directories/lockfiles and simultaneous repository changes contribute no unquestioned active time. Observed human-active seconds remain zero; inferred and user-adjusted seconds are separate.
- Open sessions are active/paused; idle, switching, explicit finish or interruption makes them completed. Completed sessions exceeding the configured minimum synchronize into Suggested Entries. Short/uncertain sessions remain locally available for explicit review or deletion. Restart completes interrupted sessions without crediting downtime. UTC timestamps handle midnight/timezone changes without inventing a new duration.
- Exact branch mappings precede wildcard matches. Multiple matching rules at the same level leave the context unassigned/nonbillable. Per-session reassignment never changes a repository default. Existing local tasks can be selected. Every saved entry needs a valid owned project (including nonbillable internal work) because that is the existing time-entry model.
- Review shows client/project, branch, date/interval, inferred duration, confidence, evidence, configured rate, cents-accurate estimated value and editable description. Draft start/duration/description/mapping persist separately from observed boundaries. Split, compatible merge, discard, nonbillable and reassignment are available. Splits apportion estimated duration and explicitly require review; merges exclude gaps/overlap and retain descriptions. Billing intervals remain explicit and editable.
- Approval is transactional and creates an ordinary reviewed time entry. Existing rate precedence, USD, rounding, prepaid treatment, overlap checks, invoice eligibility and invoice locking apply. Entry approval never issues or charges an invoice. Unique session provenance, owner/workspace locking, immutable upload IDs, optimistic review versions and deletion tombstones prevent duplicate billing/re-import.
- Four deterministic description styles use cautious branch language. User notes are preserved. Optional AI rewrites only the exact saved description after workspace enablement and explicit sharing; existing quota, timeout, source validation and unavailable-provider fallback apply. AI receives no hours, rates, raw files, diffs, local paths or client identity fields.
- Desktop and web expose review, filters by client/project/repository/branch/date/status, evidence timelines, approved-entry links and activity deletion. Today shows current local activity, pending suggestions and today's entry totals. Local activity deletion never deletes a billed entry.

## Limits and operating notes

The app must remain running to observe work; it cannot reconstruct hours while closed or asleep. Reading, planning and unchanged-file work are not observable. Generated activity outside the excluded directories can resemble human edits, so confidence never exceeds medium and every estimate must be reviewed. The 30-second poll is evidence sampling, not precise active-time measurement. Slow/unavailable Git commands time out after five seconds; 20,000 files/repository and 200 local repository approvals bound collection. Discovery stops at four levels, 2,000 directories and 100 results per selection; it skips hidden/dependency directories and directory symlinks. Re-select a workspace to discover newly added repositories.

Native local data survives network outages once the workspace has been authenticated in the running process. Reopening the app requires the existing cloud sign-in/snapshot before collection resumes; this is not a new offline billing/login engine. Synchronization runs while a signed-in main window is mounted; the native collector can retain unsent sessions while the window is absent. Web-side disable takes effect on a connected desktop's next sync; use local controls when offline. A corrupt/unwritable local store stops collection with a visible error rather than silently erasing it.

No existing Deck/Pit Boss/IDE activity adapter, project-path import, PR-title API, native system-idle API, general offline synchronization or BYOK UI was found. These are not fabricated here. Legacy CLI commit subjects remain explicit opt-in imports, and the legacy description/review flow remains available. Native session evidence currently uses commit hashes, not message text. No other app's data or external contract changes.

Run migrations before updating clients. No new environment variables or dependencies are required. Development-session lists currently return the latest 1,000 records; export/pagination for very large activity histories remains future work.

## Verification

Real PostgreSQL tests cover mapping precedence/ambiguity, duration validation, a reviewed 85-minute session at a configured $75/hour yielding $106.25, all rate levels and rounding, cross-tenant/task denial, simultaneous approvals, overlaps and active timers, draft preservation/replay, split/merge, discard/delete tombstones, invoice eligibility and locking, optional AI consent/fallback, and legacy evidence reassignment. Rust tests cover real temporary Git discovery/file metadata, no remote, canonical/renamed paths, excluded noise/symlinks, configurable gap/idle rules, branch/repository switches, repeated scans, simultaneous activity, missing observations, sleep/restart, UTC midnight and an 85-minute simulated coding session.

The isolated browser journey uses real authenticated API/database records and simulated native summaries. It edits/persists/reloads duration and description, approves on a 390px layout, and verifies a $106.25 draft in the existing invoice UI. Desktop and mobile screenshots were inspected and the review screen passed axe. This does not claim an 85-minute live human desktop observation or external AI/payment-provider verification.

The second browser journey exercises the native IPC contract with a test double backed by real API records, verifies completed-session synchronization and acknowledgement, and pauses local collection while the server is unavailable. Rust tests exercise the actual detector; the browser double does not claim live OS observation.
